# AI 생성 콘텐츠 검토 체크리스트

> AI가 생성한 교육 콘텐츠를 검토할 때 사용하세요.
> 1단계(형식)와 5단계(시간)는 `scripts/validate_markdown_v3.py` 가 자동으로 봅니다. 사람은 2~4, 6단계에 집중하세요.

---

## 📋 1단계: 형식 검증 (자동)

```bash
python scripts/validate_markdown_v3.py --md course.md
```

- [ ] error 0
- [ ] warning 을 읽고 각각 "수정" 또는 "의도적 예외" 로 판정
- [ ] 시간 리포트의 강사 발화 비율이 1/3 이하

## 🎯 2단계: 교수설계 검증 — Bowman 철칙 (15분)

### 학습 성과
- [ ] 과정·모듈 outcome이 **관찰 가능한 동사**인가 (작성한다, 시연한다, 설명한다, 구분한다). "이해한다/안다/배운다" 없음
- [ ] 제3자가 보고 달성 여부를 판정할 수 있는가
- [ ] Practice 결과물로 outcome 달성이 드러나는가

### Connect
- [ ] **학습자가 말하거나 쓰는가** (강사의 수사적 질문 하나로 끝나지 않음)
- [ ] 주제와 직접 관련된 활동인가 (아이스브레이커 아님)
- [ ] 디브리프가 있는가 (누가 무엇을 발표하는지)
- [ ] 아젠다·하우스키핑이 Connect **뒤**에 오는가 (처음 몇 분은 학습에)

**수정 요청 예:**
```
Connect에 pattern: turn-and-talk 를 넣고 params.question 을 "[주제]와 관련된 내 경험 1가지"로. notes에 디브리프 방식 추가.
```

### Concept
- [ ] 한 슬라이드 **10분 이하**
- [ ] 활동 없는 Concept가 연속 10분을 넘지 않는가 (사이에 Review)
- [ ] 학습자가 듣기 외에 하는 것이 있는가 (concept-map, graphic-organizer, 멈춤 질문)
- [ ] **need-to-know만** 있는가. "시간이 절반이면 자를 것"은 handout: 으로
- [ ] 전문 용어가 대상 수준에 맞는가

**수정 요청 예:**
```
이 Concept를 8분·7분으로 나누고 사이에 ## Review (pass-that-card) 2분. [항목]은 handout: 으로.
```

### Review
- [ ] 1~3분인가
- [ ] 전원이 참여하는가
- [ ] 바로 앞 Concept 내용을 다루는가
- [ ] 같은 활동이 3회 연속 반복되지 않는가 (습관화)

### Concrete Practice — 3요소
- [ ] **전원 참여**: 지켜보기만 하는 사람이 없는가. 역할 교대가 명시되었는가
- [ ] **상호의존**: 짝·소그룹이 서로 필요한 구조인가
- [ ] **개인 책임**: 각자 결과물이나 발언이 있는가
- [ ] 단계가 "누가 무엇을 몇 분" 수준으로 구체적인가
- [ ] 강사 관찰 포인트가 notes에 있는가
- [ ] 빠른 학습자용 추가 과제가 있는가

**실행 가능성 테스트:** 단계를 직접 따라 해본다. 막히는 곳은 추가 설명.

**수정 요청 예:**
```
Practice를 paired-practice로. params.half 를 [분]으로, 역할 교대와 결과 비교 단계 추가.
```

### Conclusion
- [ ] **학습자가 요약**하는가 (강사의 "오늘 배운 내용 ✓" 금지)
- [ ] 학습자가 자기 학습을 평가하는 요소가 있는가 (where-do-you-stand, four-square)
- [ ] 과정 마지막 Conclusion에 **action_plan** 이 있는가 (기한 + 행동 + 누구에게 말할지)
- [ ] 마지막 시간을 강사 공지·설문·정리에 쓰지 않는가
- [ ] 2분 이상인가

**수정 요청 예:**
```
Conclusion을 learning-log로 바꾸고 action_plan: "다음 주 [행동]을 하고 [누구]에게 말한다" 추가.
```

## 🎓 3단계: 전문성 검증 (10분)

### 내용 정확성
- [ ] 사실관계가 정확한가
- [ ] 최신 정보인가
- [ ] 출처가 필요한 통계·데이터는 handout에 출처 표기

### 용어 일관성
- [ ] 같은 개념을 다른 용어로 쓰지 않았는가
- [ ] 전문 용어 사용이 일관되는가

### 예시 적절성
- [ ] 한국 상황에 맞는가 (달러, 미국 사례 등 확인)
- [ ] 저작권 문제가 없는가
- [ ] 특정 집단을 차별하지 않는가

---

## 👥 4단계: 대상자 적합성 검증 (10분)

- [ ] 사전 지식 요구사항이 audience와 맞는가
- [ ] 너무 쉽거나 어렵지 않은가
- [ ] 문장이 대상이 이해할 수 있는 언어인가
- [ ] 실무·실생활에 적용 가능한가
- [ ] 활동 인원(짝/소그룹/전체)이 group_size와 맞는가
- [ ] mode(offline/online)에 맞지 않는 활동이 없는가 (`swap_activity.py --mode` 로 확인)

---

## ⏱️ 5단계: 시간 검증 (자동 + 5분)

검증기 시간 리포트에서:
- [ ] 모듈별 합계가 계획과 맞는가
- [ ] Practice가 모듈 시간의 1/3 이상인가
- [ ] 강사 발화 근사치가 1/3 이하인가
- [ ] 버퍼 10~15%가 있는가 (total_time 대비)
- [ ] Break가 50~60분마다 있는가

---

## 🔄 6단계: 흐름 검증 (10분)

### 모듈 간
- [ ] Break의 sub가 다음 모듈을 예고하는가
- [ ] 난이도가 점진적인가
- [ ] 뒤 모듈이 앞 모듈 결과물을 쓰는가

### 모듈 내
- [ ] Connect의 질문이 Concept로 이어지는가
- [ ] Concept가 Practice에 필요한 것만 다루는가
- [ ] Practice 결과가 Conclusion에서 다뤄지는가

## 📊 Bowman 철칙 통과표

| 철칙 | 확인 | 통과 |
|---|---|---|
| 설명하는 사람이 배운다 | 모든 4C에 학습자 활동이 있는가 | [ ] |
| 10분 규칙 | 활동 없는 강의 연속 10분 이하 | [ ] |
| 성과 = 관찰 동사 + 개념 | outcome에 "이해한다" 없음 | [ ] |
| 처음과 끝은 학습자 몫 | Connect 먼저, Conclusion 끝까지 학습자 | [ ] |
| 슬라이드 복사본 배포 금지 | handout은 참고 자료, 슬라이드 아님 | [ ] |
| 실습은 전원 | 역할 교대 명시 | [ ] |
| need-to-know 필터 | 자를 수 있는 것은 handout | [ ] |
| 마지막 5분은 학습자 | action_plan 있음 | [ ] |
| 학습을 평가 | 평가 문항이 "내가 무엇을 배웠고 할 것인가" | [ ] |
| 방법을 고친다 | 안 되면 활동을 바꾼다 (swap) | [ ] |

## ✏️ 수정 작업 패턴

- **작은 수정**: AI에게 섹션 단위 재요청
- **활동만 교체**: `swap_activity.py --at ... --to ...`
- **큰 수정**: Markdown 직접 편집
- **재생성**: "이 모듈의 [단계]를 [새 방향]으로 다시 작성해줘"

## 💡 검토 팁

1. 소리 내어 읽기 — 활동 지시문을 학습자에게 말하듯 읽어본다
2. 시간차 검토 — 하루 뒤 다시
3. 동료 검토 — 가능하면 다른 강사가 Practice를 직접 해본다
4. 파일럿 — 학습자 1~2명에게 Connect와 Practice만 돌려본다

## 🚨 자주 발견되는 문제

| 증상 | 해결 |
|---|---|
| "중요합니다", "필요합니다" 같은 추상 표현 | 구체 예시·수치 요청 |
| Connect가 "~해본 적 있나요?"로 끝남 | 학습자가 답을 말하는 활동 추가 |
| Concept 12~15분 | 분할 + Review |
| Practice가 "시연을 봅니다" | 전원 직접 수행으로 |
| Conclusion에 체크 표시 요약 | learning-log 등 학습자 요약으로 |
| 한국과 맞지 않는 예시 | 한국 상황으로 변경 요청 |
